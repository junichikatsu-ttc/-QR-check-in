# 構成と設計判断

## 全体

```
スマートフォンのブラウザ
  生徒: index.html + app.js        先生: teacher.html + teacher.js
          │  fetch（同一オリジン・相対パス）
          ▼
enebular HTTP トリガー  /<path>/...
          ▼
クラウド実行環境（ZIP / Node.js 22）  index.js = Hono を hono/aws-lambda で包んだもの
          │  静的ファイルは esbuild の define で index.js に埋め込み
          ▼
enebular データストア  roster / events / checkins の 3 テーブル
```

- バックエンドは Hono。`/`・`/:base`・`/:base/` の 3 通りにマウントしてトリガーのパスを吸収する
- フロントはフレームワークなし。素の JS を esbuild で 2 本（生徒 / 先生）にバンドルし、関数が配信する
- 認証は HMAC-SHA256 の自前トークン（`src/lib/token.ts`）。外部 IdP は使わない
- QR の生成は `qrcode-generator`、読み取りは `jsqr`。どちらもフロントにバンドルされ、サーバ側に画像処理は無い

## 判断の記録（ADR）

### 1. QR の中身は「署名付き・短命トークン」にする

学籍番号をそのまま QR にすると、誰でも任意の学籍番号の QR を作れる。
サーバが `SESSION_SECRET` で署名したトークン（学籍番号 + 有効期限）を QR にし、先生の端末が
読んだ文字列をそのままサーバに送って検証する。

- 有効期限は既定 5 分（`QR_TTL_SEC`）。生徒の画面は期限の 20% 手前で自動的に取り直す
- スクリーンショットを友人に送っても、数分で使えなくなる
- 署名は 160 bit に切り詰めて QR をバージョン 5〜6 程度に抑える（スマートフォンの読み取り速度のため）

**防げないこと**: 生徒が他人の学籍番号でログインすること。学籍番号しか聞かない仕様のため。
必要なら `POST /v1/auth/student` に生年月日などの第 2 要素を足す（名簿に列を増やし、Zod で検証する）。

### 2. チェックインは 1 スキャン = 1 アイテム

イベントごとに 1 アイテムへまとめる方がアクセス数は減るが、複数の先生が別々のバスで同時に
スキャンすると read-modify-write が競合して記録が消える。データストアに条件付き書き込みが無いので、
アイテムを分けて `putItem` だけで完結させる。

### 3. 名簿は 1 アイテム

学校 1 つにつき名簿 1 アイテム（2000 人まで・300KB まで）。生徒ログインとスキャンのたびに
読むので、実行コンテナ内で 30 秒キャッシュする（`src/lib/cache.ts`）。
名簿を更新した直後、別コンテナでは最大 30 秒古い名簿が見えることがある。

### 4. 先生の認証は共有パスワード 1 つ

学校の引率という用途では、先生ごとのアカウント管理よりも「当日の先生全員が同じ合言葉で入れる」方が
運用に合う。ログイン時に表示名を入れると、チェックイン記録の `by` に残る。
個別アカウントが必要になったら、`teachers` テーブルを足して `POST /v1/auth/teacher` を置き換える。

### 5. 対象外の生徒も記録する

イベントに対象クラスを指定した場合、対象外クラスの生徒の QR を読んでも**記録はする**
（「このバスに居た」事実は残したい）。一覧では「対象外のチェックイン」として分けて出し、
集計（済 / 未）には含めない。

### 6. 一覧の自動更新は 30 秒、スキャン中は更新しない

データストアのアクセス数に月次上限があるため（E4）。スキャン直後の集計はサーバの応答から
クライアント側で加算し、一覧タブを開いたときと 30 秒ごとにだけ `query` する。

## 落とし穴の固定

`test/app.test.ts` と `test/frontend-guard.test.ts` が、enebular 固有の挙動を固定している。

| テスト | 守っていること |
| :--- | :--- |
| 3 通りマウント | トリガーのパス付きでも素でも同じルートに当たる |
| `?v=__ASSET_VERSION__` の置換 | 前段キャッシュ（`.css` / `.js` が 4 時間キャッシュされる）を URL で回避 |
| 末尾スラッシュへのリダイレクト | `/qr-checkin` でも CSS / JS が読める |
| `getItem` の "Not found" が `undefined` | 初回の名簿・未チェックインが 503 にならない |
| innerHTML 不使用 | 生徒の氏名などをそのまま DOM に入れても XSS にならない |
| `byId` の id が HTML にある | 画面の白化を CI で検出 |
